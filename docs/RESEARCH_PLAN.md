# Исследовательский план, цикл 0

## Задача
Фильтрованный поиск k ближайших соседей (filtered k-NN / filtered ANN).

Дано: база X = {x_1..x_n}, x_i ∈ R^d; у каждого вектора есть атрибут (метка) a_i ∈ L.
Запрос: (q, P), где q ∈ R^d, P ⊆ L — допустимые метки.
Найти: k элементов с a_i ∈ P, ближайших к q по L2.
Качество: recall@k относительно точного ответа (brute force по отфильтрованному множеству).
Стоимость: число вычислений расстояний (не зависит от железа) + время одного потока.

Параметры сложности запроса:
- s = |{i : a_i ∈ P}| / n — глобальная селективность фильтра;
- корреляция — насколько допустимые точки находятся рядом с q
  (положительная / нулевая / отрицательная).

## Базовые методы
1. Pre-filter + brute force: O(s·n·d) на запрос, recall = 1. Сильный при малом s.
2. HNSW (hnswlib) с фильтром во время обхода. Хорош при большом s и
   положительной/нулевой корреляции.
3. Позже: ACORN-1 (2-hop расширение), планировщик по глобальной селективности.

## Гипотеза H1 (проверяется экспериментом 1)
Глобальная селективность s плохо предсказывает, какая стратегия дешевле:
при одинаковом s, но разной корреляции, лучшая стратегия различается.
Опровержение: если правило «s < порога → brute force, иначе HNSW» почти
всегда (≥95% запросов) выбирает оптимальную стратегию — H1 ложна, идея
локальной селективности не нужна.

## Гипотеза H2 (эксперимент 2, только если H1 подтверждена)
Дешёвая оценка *локальной* селективности (доля допустимых точек в нескольких
ближайших к q кластерах k-means, по заранее посчитанным гистограммам меток)
предсказывает стоимость лучше, чем s, и планировщик на её основе даёт
меньшую суммарную стоимость при recall@10 ≥ 0.95.

Механизм: оценка стоит O(c·d + m·|P|) (c центроидов, m проверяемых кластеров)
— ничтожно по сравнению с поиском — но захватывает корреляцию, которую s не видит.

Почему может не сработать:
- кластеры слишком грубые и не отражают локальную плотность допустимых точек;
- выигрыш съедается накладными расходами;
- на реальных данных корреляция слабая и правило по s уже почти оптимально;
- уже опубликованные планировщики (см. источники) делают это не хуже.

## Эксперимент 1 (синтетика, воспроизводимо)
- Данные: смесь 50 гауссиан, n = 100 000, d = 64, seed фиксирован.
- Метки: 100 значений; три режима — положительная корреляция (метка ≈ кластер),
  нулевая (случайно), отрицательная (метка из «дальних» кластеров относительно запроса).
- Селективность: 0.1%, 0.5%, 1%, 5%, 20%, 50%.
- 500 запросов на ячейку; 70% — разработка, 30% — отложенная оценка.
- Метрики: recall@10, время (num_threads=1), для brute force — число расстояний.
- Результат: таблица/график «стоимость vs s» отдельно по каждому режиму корреляции
  + доля запросов, где правило по s выбирает неоптимальную стратегию.

## Критерии успеха цикла
- Корректность: brute force совпадает с numpy-эталоном (тесты).
- H1 подтверждена, если при одинаковом s правило по s ошибается
  на ≥ 20% запросов и ошибка стоит ≥ 2× по времени в среднем на этих запросах.
